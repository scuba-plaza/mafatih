How the preview cannot drift from the real lesson

There is one implementation of the lesson text and one of the keyboard guide. The preview does not copy them. It mounts them.

Your settings

The same settings object from the profile: font, text size, vocalization, Backspace correction, keyboard, finger guide, key labels, delayed hint.

→

The app's own lesson components

The lesson text surface and the keyboard guide, exactly as the lesson pages use them. No second copy of any style, rule or layout.

→

Two places they appear

  • Practice, Recitation, Custom (real typing)
  • The Settings preview (a fixed sample, no input)
1. One code pathThe preview imports the production lesson components and passes them a fixed, real session built with the real functions (prompt, session, vocalization rules). It owns no CSS for lesson text or keys.
2. One typeBoth the lesson and the preview take the same LessonDisplaySettings type. A setting that is not in it cannot reach the lesson or the preview.
3. A setting cannot be forgottenEvery key of Settings is classified as “changes the lesson display” or “does not” in one exhaustive table. Adding a setting without classifying it fails the type check. Display settings must have a control in the Lesson group, and nothing else may.
4. Parity tests in a real browserFor every display setting and its values, the same text and the same keyboard are rendered in the real lesson and in the preview, and their DOM, fonts, sizes, colours and highlighted ranges must be identical (the preview only adds one uniform zoom).
5. A boundary testA source-reading test fails if any preview file defines lesson styles, imports anything but the shared components, or draws text itself.
6. Honest scaleOn phone the preview is at 100%. On desktop the whole preview (text and keyboard together) is zoomed to 60% and labelled “Shown at 60%”, so every proportion stays exact.

Where “Unlock all keys” goes

Screenshots of the real Practice page with the new control added. It sits in the progress row, next to “Keys unlocked 14 of 44”.

Behaviour
Pressing “Unlock” unlocks all 44 keys, letters and marks (harakat) together, and never lowers progress. The progress row then reads “44 of 44” and the existing line “All keys are unlocked.” appears; the button goes away because there is nothing left to unlock. The lesson restarts with every key, and with Auto vocalization every mark is now required. Reset progress, in Settings under Your data, still takes you back to the start.

Wording
Button “Unlock all keys”; question “Unlock all keys?”; text “Practice will use every key from now on, marks included. Reset progress, in Settings, takes you back to the start.”; “Not now” and “Unlock”. Arabic in the plan.

Not shown
While the phone's keyboard is up the progress row is hidden, and so is the button, exactly as the row is today.
